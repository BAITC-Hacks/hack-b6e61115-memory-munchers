## Принятое поведение

- Telegram @gate_os_bot и сайт используют единое ядро `Assistant`.
- 15 035 товарных карточек; обычные ответы берутся из локального каталога.
- Модель `gpt-5.4-mini`, один проход Responses, reasoning=none, максимум650 outputtokens,
  шесть последних сообщений контекста. Карточки товаров формирует сервер из БД.
- Артикул, условия, согласованный состав и подтверждение не требуют LLM.
- Подбор по задаче, Excel/Word/PDF/JPEG, аналоги, сохранённые подборы и повтор.
- Протокол менеджера после двух затруднений; технический веб-поиск отделён от
  ассортиментных данных. Продажа ограничена товарами каталога.
- Корзина меняется только по отдельному точному «да, добавь» или кнопке конкретного
  предложения. Проверяются актуальные остатки, цена, сумма количества уже в корзине.
  Подтверждение идемпотентно; вложение и ответ модели не могут дать согласие.

## Контракт интеграции

`Assistant(catalog, store, settings)`; `await reply(user_id,text,attachment=None)`;
`await confirm(user_id,proposal_id,explicit=True)`. Возвращаются `text`, `status`,
`products`, `proposal`, `trace`, `seconds`, `usage`, `cart_url`.
Одинаковый user_id должен сопровождать все действия одной клиентской сессии.
Веб использует cookie user_id, Telegram — `tg:<numeric_id>`; это разные корзины.

После создания `CatalogSync` присвоить `assistant.catalog_sync = syncer`.
Тогда Telegram тоже проверит EKT при прямом утверждении клиента, что товар есть
на сайте. Поиск по содержимому вложений этого не запускает. Синхронизация и CMS
принадлежат принимающей сессии: `app/catalog_sync.py`, `app/main.py`.

Серверные бюджеты: весь reply/confirm7.2с, planner5.2с, research6.6с,
проверка EKT1.6с, missing-product lookup2с. Telegram использует общие7.2с
на скачивание/разбор/ответ. При превышении — честный незавершённый результат,
не ложное сообщение об успешном подборе. Доставка Telegram и загрузка клиентом
файла не входят в измерения серверной обработки.

## Ограничения, которые нельзя скрывать при сдаче

1. Корзина своя, SQLite. Публичный API переноса в браузерную корзину EKT не найден.
   Прямая ссылка открывает актуальную корзину ассистента; это не checkout EKT.
   Для настоящего оформления нужен переносимый cart-token/API партнёра.
2. История — сохранённые подборы, не оплаченные заказы EKT. API прошлых заказов нет.
3. Большой Excel читается потоком: первые100строк/4листа, до20 000символов и8MiB
   фактически прочитанного XML. Пользователь видит предупреждение о фрагменте.
   Полная обработка произвольной большой спецификации за8с не заявляется.
4. JPEG даёт кандидатов по маркировке, не точную идентификацию изделия; фото EKT
   может быть общим для серии. Поиск соблюдает ток, кривую, полюса и отключающую
   способность. Совместимость с установкой требует достаточных исходных параметров.
5. PDF-сканы без текста требуют изображения страниц; старые DOC/XLS требуют
   пересохранения. Формулы и встроенные инструкции не исполняются.
6. Не запускать два Telegram polling процесса на одном токене. Для Railway-сайта
   оставить TELEGRAM_BOT_TOKEN пустым, пока локальный polling не передан отдельно.
