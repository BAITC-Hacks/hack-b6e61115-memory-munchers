# Запуск EKT Assistant в Docker

Инструкция относится к ветке `alternative_version` репозитория `BAITC-Hacks/hack-b6e61115-memory-munchers`. Docker запускает веб-сайт с чатом и отдельную локальную корзину прототипа. Встроенного подключения к производственной корзине ekt.kz нет; `/health` сообщает `ekt_cart_bridge: false`.

## Требования

- Git и Docker с плагином Compose. На Windows — Docker Desktop в режиме **Linux containers** и работающий WSL 2.
- Docker Engine должен отвечать: `docker info`. Наличие команды `docker --version` само по себе не означает, что Engine запущен.
- Доступ к Docker Hub, Debian packages и PyPI для первой сборки. Для дальнейшего запуска собранного образа эти источники не нужны.
- Практический ориентир для демо: 2 CPU, 2 ГБ доступной памяти и несколько ГБ свободного места для образов. Это ориентир, а не результат нагрузочного теста.
- Python, Node.js и PostgreSQL на компьютере для этого способа запуска не нужны.

## Быстрый старт: Windows PowerShell

Сначала запусти Docker Desktop и дождись готовности Engine. Выполни команды из папки, в которую хочешь клонировать проект:

```powershell
git clone --branch alternative_version --single-branch https://github.com/BAITC-Hacks/hack-b6e61115-memory-munchers.git ekt-assistant
Set-Location ekt-assistant
Copy-Item .env.example .env
docker compose up --build -d --wait --wait-timeout 180
Invoke-RestMethod http://127.0.0.1:8001/health
```

`Copy-Item` выполняется только при первом запуске в новом клоне: существующий `.env` сохраняй. Первая сборка скачивает Python и зависимости; ограничение `180` относится к ожиданию готовности контейнера после сборки. Если версия Compose не поддерживает `--wait`, выполни `docker compose up --build -d`, затем проверяй `docker compose ps` и `/health`.

Открой [http://127.0.0.1:8001](http://127.0.0.1:8001). На чистом volume `/health` должен вернуть HTTP 200, `status: "ok"`, `catalog_products: 15035`, `openai_configured: false`, `telegram: "not_configured"`. Количество товаров может увеличиться после подключения синхронизации. Контейнер станет `healthy`, когда HTTP работает и каталог содержит хотя бы одну карточку.

## Быстрый старт: Linux / macOS

Для Linux установи Docker Engine и Compose plugin; для macOS — Docker Desktop. Команды ниже предназначены для bash/zsh:

```bash
git clone --branch alternative_version --single-branch https://github.com/BAITC-Hacks/hack-b6e61115-memory-munchers.git ekt-assistant
cd ekt-assistant
cp .env.example .env
docker compose up --build -d --wait --wait-timeout 180
curl --fail http://127.0.0.1:8001/health
```

Далее сайт доступен по тому же адресу. Для запуска только каталога файл `.env` вообще не обязателен: у всех переменных Compose есть значения по умолчанию.

## Что работает без внешних доступов

В образ входит `data/raw_details.jsonl`: 15 035 карточек, примерно 48,7 МБ. Файл отслеживается в Git и не требует Git LFS или скачивания каталога после клонирования. Это сохранённая выгрузка каталога партнёра, а не актуальные остатки на момент просмотра.

Без ключей доступны сайт, поиск и карточки каталога, характеристики, сохранённые ссылки на сертификаты, подбор аналогов, справка об условиях, локальная история сессии и создание предложения для корзины. Ссылки на внешние сертификаты требуют сети при открытии. Для некоторых карточек поиск ссылок выполняется на ekt.kz; при недоступности сайта интерфейс сообщает об ограничении.

Без OpenAI используется локальная обработка понятных каталожных запросов. Свободные сложные формулировки и распознавание фото JPEG/PNG требуют `OPENAI_API_KEY`. Excel `.xlsx`, Word `.docx` и текстовый PDF извлекаются локально; старые `.xls`/`.doc` не поддерживаются. Встроенного OCR сканированных PDF нет: для такого файла нужен текстовый PDF либо отдельное фото для распознавания моделью.

**Без доступа EKT подтверждение добавления в корзину не завершается:** приложение обязано перепроверить остаток через API и не доверяет старому снимку. Это штатный отказ, а не ошибка запуска Docker. Полный сквозной сценарий «подбор → явное подтверждение → добавление → ссылка на актуальную локальную корзину» требует рабочего EKT API. Фоновая синхронизация для этого не обязательна: при подтверждении остаток проверяется отдельно.

## Настройка полного сценария

Отредактируй локальный `.env` в UTF-8. Пустые значения оставляй у неиспользуемых интеграций. Compose читает `.env` с компьютера и передаёт перечисленные переменные процессу; файл не копируется в образ. После изменений выполни `docker compose up -d --force-recreate --wait --wait-timeout 180`: обычный `restart` новые значения `.env` не применяет.

- `OPENAI_API_KEY` — API-ключ для сложного подбора и фото. `OPENAI_MODEL` и `OPENAI_RESEARCH_MODEL` — модели, доступные твоему API-проекту; исходное значение приложения — `gpt-5.4-mini`.
- `EKT_API_USER`, `EKT_API_PASSWORD` — доступ к тестовому/партнёрскому API; `EKT_API_BASE` по умолчанию `https://ekt.kz/api`. Приложение читает `/products` и `/products/detail` и не оформляет заказ на стороне EKT.
- `CATALOG_SYNC_ENABLED=1` — включить фоновое обновление раз в 300 секунд. В примере стоит `0`, чтобы новый клон запускался на включённом снимке без внешних доступов. При включении обновляется перечень и ограниченные партии карточек; не все остатки становятся свежими одновременно.
- `CMS_ADMIN_TOKEN` — собственное непустое значение, если нужен экран [CMS](http://127.0.0.1:8001/admin). Введи это же значение в форме доступа CMS. API принимает заголовок `X-Admin-Token` либо `Authorization: Bearer ...`. В Docker токен нужен даже при открытии `localhost`: запрос с компьютера приходит через Docker gateway, а не с loopback контейнера.
- `PUBLIC_BASE_URL` — полный адрес сайта без завершающего `/`, если нужен внешний адрес в ссылках. Для локального веб-чата можно оставить пустым.
- `MODEL_TIMEOUT_SECONDS`, `RESPONSE_TIMEOUT_SECONDS` — бюджеты ответов модели и ассистента. Код ограничивает их сверху 5,2 и 7,2 секунды; HTTP-обработчик имеет общий бюджет около 7,6 секунды. Это пределы ожидания и fallback, а не гарантия успешного ответа внешнего сервиса.
- `EKT_HTTP_PORT` — порт компьютера, по умолчанию `8001`. `EKT_BIND_HOST` — интерфейс компьютера, по умолчанию `127.0.0.1`.

`TELEGRAM_BOT_TOKEN` и NVIDIA-переменные в этот Compose не передаются. `scripts/run_site.py` дополнительно отключает Telegram polling; запуск веб-контейнера не создаёт второго Telegram-бота. `DATABASE_URL` приложением не используется: SQLite находится в `/app/data`.

## Проверка после запуска

В PowerShell:

```powershell
docker compose ps
docker compose logs --tail 80 web
$health = Invoke-RestMethod http://127.0.0.1:8001/health
$health | Select-Object status, catalog_products, openai_configured, telegram, ekt_cart_bridge
(Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8001/).StatusCode
(Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8001/static/site.js).StatusCode
```

Ожидается `healthy`, `status=ok`, непустой каталог, HTTP 200 для страницы и скрипта. Затем пройди в браузере:

1. Запрос `010500006_`: карточка, цена и остаток с указанием источника, характеристики и сертификаты.
2. Запрос `310100024_`: отсутствующая позиция и предложения аналогов с объяснением.
3. Запрос `Какие оплата, доставка и минимальная партия?`: содержательный ответ.
4. Выбери товар и количество. До явного подтверждения корзина остаётся пустой.
5. Нажми подтверждение. При рабочих EKT-доступах и достаточном остатке товар появляется в локальной корзине; выданная ссылка открывает ту же корзину. Без доступа к остаткам ожидается понятный отказ и пустая корзина.

Для проверки сохранения состояния добавь предложение или сообщение в своей тестовой сессии, выполни `docker compose restart web`, дождись HTTP 200 и открой сайт в том же браузере. SQLite и cookie сессии должны сохранить историю и состояние. Cookie разных браузеров ведут к разным корзинам.

## Данные и повторный запуск

Compose создаёт volume `ekt-assistant_data` и монтирует его в `/app/data`. Там сохраняются `catalog.sqlite`, `assistant.sqlite`, `cms.sqlite` и служебные файлы. Снимок помещается в образ отдельно — `/app/seed/raw_details.jsonl`. При первом запуске на пустом volume скрипт копирует его в `/app/data`, после чего строится каталог SQLite. Повторная сборка и перезапуск не заменяют существующую базу новым seed.

Обычные команды одинаковы в PowerShell и bash:

```text
docker compose stop
docker compose start
docker compose restart web
docker compose down
docker compose up -d --wait --wait-timeout 180
docker compose logs --tail 100 web
docker volume inspect ekt-assistant_data
```

`stop` останавливает контейнер, `start` запускает его снова. `down` удаляет контейнер и сеть, но сохраняет named volume. Не добавляй `-v` к обычной остановке: эта опция удаляет volume со всей историей, корзинами и CMS. Физические файлы volume находятся в хранилище Docker, на Windows — внутри Linux VM, а не в локальной папке `data/` репозитория.

Для резервной копии согласованных SQLite останови приложение, скопируй каталог и запусти контейнер снова. Пример для PowerShell:

```powershell
docker compose stop web
New-Item -ItemType Directory -Force backups | Out-Null
$backupDir = Join-Path (Resolve-Path backups) ('data-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
docker compose cp web:/app/data $backupDir
docker compose start web
```

Копия содержит историю этого экземпляра. Для переноса в отдельный новый экземпляр останови его контейнер, восстанови содержимое каталога `data` в `/app/data` через `docker compose cp`, затем запусти его. Не объединяй SQLite-файлы двух экземпляров.

## Другой порт и демонстрация с телефона

Если `8001` занят, установи в `.env` `EKT_HTTP_PORT=8010` и снова выполни `docker compose up -d`. Адрес изменится на `http://127.0.0.1:8010`; порт внутри контейнера и healthcheck остаются `8001`.

Для телефона в одной локальной сети установи `EKT_BIND_HOST=0.0.0.0`, пересоздай контейнер и открой `http://IP_КОМПЬЮТЕРА:8001`. Адрес компьютера смотри через `ipconfig` в Windows или `ip addr` в Linux; для нового порта используй его значение. Доступ зависит от разрешения входящих подключений в локальном firewall. После демонстрации верни нужный интерфейс в `.env`.

## Если не запускается

- **`dockerDesktopLinuxEngine` / `Cannot connect to the Docker daemon`:** запусти Docker Desktop, выбери Linux containers и дождись успешного `docker info`. Это недоступный Engine; изменение кода проекта не поможет.
- **Сборка не скачивает базовый образ или зависимости:** проверь доступ к Docker Hub, Debian и PyPI, затем повтори `docker compose build`. Для первого build нужен интернет.
- **`address already in use` / `port is already allocated`:** смени `EKT_HTTP_PORT` в `.env`; существующее приложение на этом порту останавливать не обязательно.
- **`COPY data/raw_details.jsonl: not found`:** проверь ветку и наличие отслеживаемого файла командой `git ls-files data/raw_details.jsonl`. Сборку запускай из корня клона. Каталог не скачивается при запуске автоматически.
- **`unhealthy` или слишком долгий `starting`:** посмотри `docker compose logs --tail 100 web`. Первый запуск создаёт SQLite из 15 035 карточек. Проверь свободное место и память; при медленной машине повтори ожидание или увеличь `--wait-timeout`.
- **`/admin` открывается, но API возвращает 401/403:** задай `CMS_ADMIN_TOKEN`, пересоздай контейнер и введи то же значение в CMS. Пустой токен не даёт доступ через Docker gateway.
- **Карточка есть, но добавить нельзя:** наличие в seed не означает успешную проверку актуального остатка. Проверь наличие EKT-доступов, доступность API и запрошенное количество. По `openai_configured` нельзя судить о работе EKT.
- **`openai_configured: true`, но сложный запрос/фото не обработан:** флаг означает, что ключ задан, а не что вызов API прошёл. Проверь доступность выбранной модели, квоту и сообщение интерфейса; каталог продолжает работать локально.
- **Изменил `.env`, но поведение прежнее:** используй `docker compose up -d --force-recreate`; `restart` не перечитывает переменные окружения контейнера.
- **После обновления образа каталог остался прежним:** существующий volume сохраняет базу; это ожидаемо. Для обновления используй доступ EKT и синхронизацию. Не удаляй volume ради обычного обновления кода.

## Границы проверки

Docker упаковывает приложение и данные, но не предоставляет EKT-доступы, OpenAI-кредиты, подключение к действующей CMS магазина или производственной корзине. Успешный `/health` подтверждает старт и загрузку каталога; сквозной сценарий с актуальными остатками проверяется отдельно. Развёртывание в Railway и изменение действующего сайта в эти команды не входят.

Фактические результаты подготовки этой ветки фиксируются в итоговом отчёте и `PROGRESS.md`. Конфигурацию можно проверить без Engine командой `docker compose --env-file .env.example config --quiet`; она не выводит значения переменных. Для подтверждения Linux-сборки нужен успешный build и запуск реального контейнера.
