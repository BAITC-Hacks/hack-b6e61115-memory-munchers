Обработку обычных вопросов переводим на локальную БД. Живое наличие проверяется
перед подтверждённым добавлением; фоновое обновление БД раз в 5 минут собирается
интеграционной сессией в `app/catalog_sync.py`.

## Полные сценарии и защита времени

На gpt-5.4-mini свободный подбор с реальным вызовом каталога прошёл за **2.999 / 1.552 с**.
Два сквозных прогона: поиск → предложение → пустая корзина до подтверждения →
«да, добавь» → ровно 2 штуки → ссылка соответствует текущей корзине. Все проверки true.
Результат: `data/benchmark_live_agent.json`.

После этих замеров обычные `product_details` переведены с HTTP на `catalog.get`:
ответ честно помечается снимком локальной базы. Live остаётся только на подтверждении.

- `Assistant.reply/confirm`: общий бюджет **7.2 с**, включая ожидания.
- OpenAI: максимум **5.2 с**, без повторных запросов; один проход планировщика.
  Явный технический веб-поиск идёт сразу в research и получает до **6.6 с**.
- Каталог: **1.6 с** целиком, включая lock; две попытки по 0.7 с с паузой 0.1 с.
- Проверка корзины: остатки запрашиваются параллельно, максимум четыре одновременно.
- Telegram: получение/разбор вложения + обработка ограничены **7.2 с**; на получение
  файла отдельно максимум 2.5 с. Доставка сообщения сетью Telegram — внешний этап.
- При занятости пользовательского диалога новый запрос не встаёт в длинную очередь.
- При превышении бюджета возвращаются найденные данные локальной БД или ясное
  уточнение/отказ. Это **не считается завершённым подбором**. Корзина не изменяется.
- Вопросы об оплате/доставке сохраняют согласованный состав. Изменение состава,
  новое предложение и явная отмена инвалидируют прежнюю кнопку.

## Проверки

Финальный прогон: **112 тестов и 66 подслучаев** прошли за **37.10 с**.
Файлы: `tests/test_agent.py`, `test_catalog.py`,
`test_store.py`, `test_attachments.py`, `test_grounding.py`, `test_latency.py`, `test_web.py`.
Времена загрузки каталога (~10 с) относятся к старту процесса, а не к ответам после readiness.

`scripts/verify_fast_flows.py` расширяет реальные проверки на память, вложения,
JPEG и менеджера с веб-поиском; итог в `data/fast_flow_results.json`. Успешность
отмечается отдельно от времени — fallback не превращается в успешную обработку.

В расширенном живом прогоне: карточка по артикулу **0.006 с**, аналог **0.009 с**,
подтверждение с живым остатком **0.529 с**, повтор сохранённого подбора **1.32 с**,
небольшой Excel **1.32 с**, фото **1.88 с**, свободный подбор **2.81 с**.
Реальный веб-поиск с источником ABB завершился за **6.60 с**. Время включает
обработку ассистентом, но не загрузку файла пользователем и доставку Telegram.

Большой исходный Excel (13 660 993 байта) теперь читается потоком за **0.014 с**:
фактически прочитано 199 234 байта XML. Ограничения100строк/4листа/20kсимволов
видны в предупреждении. Это обработка фрагмента, не всего документа.

## Пределы проверенного результата

Само ограничение времени не гарантирует завершение произвольного запроса при
недоступном OpenAI/сайте/Telegram. Оно гарантирует ограниченное ожидание и честный
ответ с сохранной корзиной. Внешний checkout и старые заказы EKT требуют API партнёра.
Сайт и прод-корзины EKT не изменялись.
